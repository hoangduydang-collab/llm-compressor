Goal 06 / engineering field note · Planned · benchmark-gated

Packed NVFP4 W4A8 on Hopper

Future work: test whether official NVFP4 checkpoints can keep four-bit weights packed on Hopper while converting fragments inside the GEMM for FP8 Tensor Core execution.

Design complete · prototype committed Zero hardware results yet Reuse Humming, not a clean-sheet kernel
Contents01 Why02 Direction03 Gates & sub-tasks04 Staged path05 Evidence

01 / WhyPreserve the value of packed NVFP4 on Hopper

Official model releases increasingly ship NVFP4 checkpoints for native Blackwell FP4 execution. Hopper has FP8 Tensor Cores but no native FP4 multiply.

Expanding those weights to FP8 at load time improves compatibility but loses much of NVFP4's memory and bandwidth advantage. This investigation asks whether H100/H200 can keep weights packed at four bits, convert only the fragments needed by each GEMM, and execute the multiply on FP8 Tensor Cores.

Plan only

There are no hardware measurements yet. This page describes a benchmark-gated direction, not a demonstrated performance result or production commitment.

02 / DirectionExtend an existing backend, fail closed to Marlin

The preferred path is a narrow specialization of the existing Humming packed E2M1/FP8 backend. It already provides the closest upstream machinery for packed weights, dynamic FP8 activations, and Hopper WGMMA.

The established vLLM Marlin W4A16 path remains the compatibility baseline and fallback. Unsupported shapes, scale layouts, or model structures must route to Marlin rather than silently selecting an unqualified kernel.

The prize, in design-time arithmetic: 4-bit packed weights are half the memory and bandwidth of the 8-bit expansion Hopper would otherwise use — if, and only if, the in-kernel conversion is cheap enough. That "if" is exactly what 6a measures.

03 / Decision gatesContinue only with evidence

The dense proof must pass all three categories before serving or MoE work begins:

  • Correctness: finite, deterministic outputs that match the W4A8 reference within the predeclared tolerance.
  • Memory: no persistent FP8-expanded weight and storage close to the packed W4A16 baseline.
  • Performance: useful improvement in at least one decision-relevant serving bucket without materially slowing the primary bucket.

If correctness or memory fails, stop. If performance is not useful, retain the evidence but do not begin production integration.

  • 6a · Dense proof of concept vs upstream NVFP4 W4A16 Marlin and load-expanded W8A8 — the gate for all MoE production work

04 / Future workStaged path

  1. Run the one-layer SM90 probe for compilation, numerical correctness, packed memory, and actual FP8 WGMMA use.
  2. Qualify a dense proof of concept across representative shapes and serving batch sizes.
  3. Integrate an opt-in dense serving path and compare it with Marlin W4A16 and load-expanded W8A8.
  4. Specify fused-MoE production work separately, and only after every dense-stage gate passes.
