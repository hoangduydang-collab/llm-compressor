> ## ⚠ CORRECTION (2026-09-16) — this run used the wrong branch of AA's own rule
>
> This note calls temperature 0.6 / top_p 1.0 the "public methodology" and the
> 1.0 / 0.95 run an "ablation". That is backwards for GLM-5.3.
>
> AA publishes a generic default of 0.6 / 1.0 **and overrides it with the model
> creator's recommended config whenever the lab publishes one.** Z.ai recommends
> temperature 1.0 / top_p 0.95 for GLM-5.3, so the lab-override branch is the
> AA-faithful setting and **0.6 / 1.0 is the ablation**. The AA GPQA arm already
> moved onto this rule in `189e3ac7`; the AA-LCR runner was left behind until
> `aa_lcr_v11.py` was corrected on 2026-09-16.
>
> Also: the 131,072 cap is **not an AA-published figure**, as §Truncation below
> implies. It is AA's max-output policy applied to Z.ai's disclosed 128K output
> maximum for GLM-5.3.
>
> The 71.33% measurement stands; only its provenance label is wrong. The
> Z.ai-sampling result is **77.67%** — see
> [`2026-09-16-glm53-aa-lcr-v11-zai-sampling.md`](2026-09-16-glm53-aa-lcr-v11-zai-sampling.md),
> which also shows the raised cap contributed nothing and that this run's 32
> truncations were a low-temperature artifact rather than a budget shortfall.

### Truncation

**32 / 300** traces hit the 131,072 cap (`finish_reason=length`), all with
empty final answers. The other 268 stopped naturally.

- Uncapped accuracy among `stop` traces: **214 / 268 = 79.85%**.
- If every truncated item would have scored correct, the ceiling is
  246 / 300 = **82.0%**. That is a bound, not a measurement.
- 131k is too small for this bench’s tail. A raised-cap rerun should use
  **262,144** (same number as the GPQA diagnostic) and a KV pool that can
  hold ~115k prompt + that cap. The 598,848 two-node pool can; a 1-node
  ~165k pool cannot.

Completion tokens: min 207, mean 16,929, max **131,072**. Prompt tokens:
min 76,820, mean 97,318, max 114,611.
