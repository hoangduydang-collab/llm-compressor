# GLM-5.3 AA-LCR v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a resumable, secret-safe AA-LCR v1.1 public-methodology runner for the existing GLM-5.3 W4AFP8 TP=16 endpoint and the external GPT-5.6 Luna (medium) judge.

**Architecture:** A single focused Python module exposes `prepare`, `generate`, `judge`, and `summarize` commands. It pins AA's v1.1 dataset, checkpoints candidate and judge phases independently in SQLite, calls the SGLang endpoint through its OpenAI-compatible Chat Completions API, and calls the official OpenAI Responses API for judging. CPU-only Kubernetes Jobs stage a dedicated environment and run canary/full clients without embedding credentials.

**Tech Stack:** Python 3.12, standard-library CSV/ZIP/SQLite/HTTP, `openai==3.8.0`, `tiktoken==0.14.0`, pytest, Kubernetes Jobs and Secrets.

## Global Constraints

- Dataset revision is exactly `9a77ef56b717057ade24ceab4d273712a0b4f19e`.
- Extracted-text ZIP SHA-256 is exactly `5e839249826f6b9bd5324f0d139089c9dc481ccb3f212a6dfad00c51045d9d8a`.
- Benchmark identity is “AA-LCR v1.1 public-methodology reproduction,” never an official AA score.
- Population is 100 questions × 3 repeats; pass@1 is `CORRECT / 300`.
- Candidate settings are temperature `0.6`, top-p `1.0`, maximum output `131072`, reasoning enabled, concurrency `2`.
- Judge settings are model `gpt-5.6-luna`, reasoning effort `medium`, standard mode, and the exact pinned v1.1 prompts.
- Only candidate `message.content` is judged; `reasoning_content` is retained separately.
- `OPENAI_API_KEY` is accepted only from the process environment and is mounted only from Kubernetes Secret `hd-openai-aa-judge`.
- Returned candidate responses are immutable terminal records; resume retries transport gaps only.
- Candidate and judge phases remain independently resumable.
- Any incomplete candidate or judgment population suppresses the headline score.
- No Kubernetes write, external API call, candidate generation, or GPU-service traffic occurs during implementation or CPU test execution.

```python
class JudgeProtocolError(ValueError):
    pass


def canonical_json(value: object) -> str:
    return json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(",", ":"))


def sha256_text(value: str) -> str:
    return hashlib.sha256(value.encode("utf-8")).hexdigest()


def parse_judge_verdict(text: str) -> str:
    try:
        value = json.loads(text)
    except json.JSONDecodeError as exc:
        raise JudgeProtocolError("judge output is not JSON") from exc
    if not isinstance(value, dict) or set(value) != {"verdict"}:
        raise JudgeProtocolError("judge JSON must contain only verdict")
    verdict = value["verdict"]
    if not isinstance(verdict, str) or verdict.upper() not in {"CORRECT", "INCORRECT"}:
        raise JudgeProtocolError("judge verdict must be CORRECT or INCORRECT")
    return verdict.upper()
```
