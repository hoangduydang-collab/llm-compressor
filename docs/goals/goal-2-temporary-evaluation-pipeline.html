01 / PurposeComparable model-to-model evidence

Every checkpoint receives the same rendered prompts, exact examples, generation seeds, decoding settings, and scoring implementation.

The completed deliverable is a working paired evaluation pipeline with fail-closed contract checks and reproducible raw evidence. It provides a controlled quantization-fidelity signal for internal decisions.

It is deliberately not a public-leaderboard score: the evaluation uses seeded subsets and a fixed internal contract rather than each benchmark's full public protocol.

03 / Results · speculative decodingUp to 2.5× faster decoding, free of quality risk

Newest (27–29 July). Speculative decoding pairs the full model with a small "drafter" that proposes several tokens per step; the full model then verifies them all at once. Every token is still checked by the full model, so output quality is untouched by construction — the only question is speed. It is the single largest decode-speed lever measured in this program, larger than any kernel or quantization change below.

The size of the win is set by what the model is writing — predictable content (code, structured output) drafts easily, creative prose does not — and not by prompt length or load:

Per-user decode speed with speculation, by traffic type · in-house 4-bit model, one 8-GPU node · off-the-shelf community drafter, quantized to 4-bit in-house
TrafficUsersBest draft depthSpeed per user, with vs withoutSpeedup
Code / structured16 tokens346 vs 137 tok/s2.53×
Code / structured105 tokens + fast drafter kernel155 vs 75 tok/s2.07×
Mixed real chat13 tokens250 vs 138 tok/s1.81×
Creative writing12 tokens186 vs 137 tok/s1.36×
Creative writing102 tokens97 vs 81 tok/s1.21×

Server capacity rises alongside per-user speed — at ten users on code the same 8 GPUs go from ~706 to ~1,428 total output tok/s — so this is not a latency-for-throughput trade. And the drafter accepts our 4-bit model's guidance exactly as well as the vendor's own 8-bit release, while our stack is 22–40% faster in absolute terms in every measured cell.

The three tuning levers, in order of value
LeverRecommendationWorth
Draft depth (tokens proposed per step)Tune per traffic class: 5–6 for code, 2 for creative writing — the reference default (3) is wrong for bothup to ~12%
Drafter kernelSwitch the drafter to the Humming kernel only under load+2.3% at 10 users; nothing at 1
Drafter precisionServe the 4-bit drafter — free in draft quality, never hurts~2.6% single-user, <1% under load

Caveats

Prefill-dominated traffic (long prompts, short answers) gains almost nothing — speculation accelerates the writing, not the reading. Numbers come from NVIDIA's SPEED-Bench (clean subset) and support configuration decisions, not leaderboard comparison. All conclusions were hardened by a replicated re-measurement (35 serves on one node, 29 July) that corrected three earlier readings.

Full study: M3_OFFICIAL_SPECDEC_RESULTS.html; complete write-up: docs/m3-specdec-eagle3.md. Detailed sweeps: appendix.

05 / Harness of recordThe official pipeline is now the harness of record

The migration finished: MiniMax-M3 runs on the team's official evaluation pipeline (AICloud/benchmarks — lm-eval 0.4.10 over its API backend against a self-deployed, pinned vLLM 0.24.0 endpoint). On it, the in-house GPTQ arm earned a seven-task breadth verdict (recovery 97.4–101.1% on all seven tasks, token spend within 2% of BF16), published in M3_OFFICIAL_QUALITY_RESULTS.html. Because the official pipeline uses different tasks, greedy decoding, and loglikelihood multiple-choice scoring, its numbers are not comparable to the stopgap table above.

Since generalized beyond MiniMax-M3

The same paired protocol produced a three-arm GLM-5.2 evaluation (BF16 vs community W4AFP8 checkpoints, self-hosted on SGLang — GLM52_OFFICIAL_EVAL_RESULTS.html: Phala's AWQ-produced W4AFP8 is clean, the M3 AWQ pathology does not replicate) and a W2A16-vs-BF16 A/B on the sub-4-bit track (Goal 4). The remaining sub-task is 2g: the seven-task breadth run for the quality-clean AWQ r6 recipe.

What the result supports

Our in-house GPTQ W4A8 remains within a few points of BF16 on every task. Official MXFP8 is roughly baseline-equivalent and is the strongest quant overall. The external AWQ comparator loses materially more quality, especially on GPQA and AIME25.

Harness setup (interim)

  • Framework: EleutherAI lm-evaluation-harness 0.4.12, direct vLLM backend.
  • Models: in-house GPTQ W4A8, in-house AWQ W4AFP8 (smoke-gated), cyankiwi AWQ W4A16, official MXFP8 W8A16, and official BF16.
  • Tasks: GPQA-Diamond 100, MMLU-Pro 100, GSM8K-CoT 100, and the full 30-question AIME25 split.
  • Generation: seeds 42/1234/4158, thinking enabled, temperature 1.0, top-p 0.95, maximum 16,384 generated tokens.
  • Serving: TP8 for quantized and MXFP8 checkpoints; BF16 uses TP16 across two nodes.

The preflight contract pins the sample manifest, tokenizer, chat template, rendered prompts, and evaluation config. Cross-run gates require those inputs to match before scores are compared.

Drafter precision (4-bit vs full-precision drafter), 12-cell A/B.
