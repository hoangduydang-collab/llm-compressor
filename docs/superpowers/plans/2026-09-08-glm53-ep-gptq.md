# GLM-5.3 EP GPTQ Implementation Plan

> **For agentic workers:** Use the `executing-plans` skill to implement this plan task by task, inline. Steps use checkbox (`- [ ]`) syntax for tracking. Do not delegate by default.

**Goal:** Complete expert-local GPTQ in the existing GLM sequential pipeline, preserving calibration coverage and checkpoint persistence, with phase evidence for the later storage investigation.

**Architecture:** Keep `LinearExperts2D`'s existing gathered-token forward for all-expert calibration. Adapt MoEQuant's expert-local versus replicated Hessian ownership to llm-compressor; retain the existing GPTQ solver, distributed offload, and collective export. Separate owner-local computation from globally ordered parameter publication.

**Tech Stack:** Python, PyTorch distributed/Gloo/NCCL, Transformers GLM-MoE-DSA, llm-compressor, compressed-tensors, loguru, pytest.

**State:** Tasks 1–5 implemented; Task 6 CPU qualification passed (212 passed, 4 CUDA skips). The bounded NCCL gate is pending; Task 7 representative execution remains pending. See [implementation evidence](../../glm53-ep-gptq-implementation.md). The owner approved the design direction on 2026-09-08. Baseline design commit: `1adaa565` on `duy-branch`.

## Global constraints

- Never build what already exists: reuse decisions and source references below govern every task.
- Initial supported workload: single-node GLM-5.3, decoder-layer sequencing, all experts calibrated, one EP group spanning all ranks.
- Keep a common module tree and shared CPU/disk indexes on every rank.
- Preserve exact input coverage and contribution counts; floating-point comparisons use tolerances.
- Validate equal, nonzero dataloader step counts collectively before the walk.
- Preserve standard distributed GPTQ and AWQ defaults when EP is disabled.
- Do not change GPTQ damping, activation ordering, fallback, weight format, or solver kernel as part of EP.
- Do not build another loader or distributed checkpoint writer.
- Keep storage placement and prefetch settings fixed within each EP comparison.
- This plan is not an execution packet or a claim of SGLang compatibility. Representative/full GPU work needs the packet specified by `PLANNER_EXECUTOR_PROTOCOL.md`.

### Why this selection

Adapting the complete MoEQuant runner also requires replacing its DeepSeek architecture assertion, 163-shard naming assumptions, loading/export path, and calibration slicing. Its published token dispatcher visits only routed experts. For this workload, extending the existing gathered-token adapter preserves every-token/every-expert calibration with fewer independent changes. The reuse is the existing adapter plus MoEQuant's ownership split, not a new communication implementation or a port of different GPTQ math.

The first exposed EP mode supports weight-only GPTQ and the existing dynamic-activation W4AFP8 recipe. The inspected compressed-tensors W4AFP8 preset has dynamic per-token activations and no activation observer. Static activation observers require additional semantics: an owner accumulating an EMA on concatenated inputs is not equivalent to averaging rank-local EMAs. Reject such configurations before calibration; do not automatically substitute an observer or change the recipe. Problem 2 can later select the serving contract explicitly.

- [ ] Add this numerical regression using the real accumulator:

```python
@torch.no_grad()
def test_gathered_hessian_preserves_rank_contributions():
    from llmcompressor.modifiers.gptq.gptq_quantize import accumulate_hessian

    module = torch.nn.Linear(5, 3, bias=False)
    generator = torch.Generator().manual_seed(23)
    shards = [torch.randn(n, 5, generator=generator) for n in (2, 5, 3)]
    reference_h = make_empty_hessian(module)
    reference_n = torch.zeros(())
    for shard in shards:
        reference_h, reference_n = accumulate_hessian(
            shard, module, reference_h, reference_n
        )
    gathered_h, gathered_n = accumulate_hessian(
        torch.cat(shards), module, make_empty_hessian(module), torch.zeros(()),
        num_added=len(shards),
    )
    assert gathered_n.item() == reference_n.item() == 3
    torch.testing.assert_close(gathered_h, reference_h, rtol=1e-5, atol=1e-6)
    torch.testing.assert_close(
        gathered_h / gathered_n, reference_h / reference_n, rtol=1e-5, atol=1e-6
    )
```

Keep the override keyword-only and leave accumulation arithmetic unchanged. Add the following scoped helpers alongside the existing `_STATE`:

```python
def get_expert_hessian_contributions() -> int | None:
    return getattr(_STATE, 'hessian_contributions', None)


@contextlib.contextmanager
def expert_hessian_contributions(count: int):
    if isinstance(count, bool) or not isinstance(count, int) or count < 1:
        raise ValueError('count must be a positive integer')
    previous = get_expert_hessian_contributions()
    _STATE.hessian_contributions = count
    try:
        yield
    finally:
        _STATE.hessian_contributions = previous
```

from itertools import zip_longest


def solve_rounds(rank_to_modules):
